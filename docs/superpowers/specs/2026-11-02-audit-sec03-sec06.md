# Audit SEC-03–SEC-06 Design

## Intent

Resolve the next three security work packages from the original audit: SEC-03 (Windows updater supply-chain safety), SEC-04 (Valheim mod path containment), and SEC-05/SEC-06 (secret output and file-permission hardening).

## Goals

- Windows self-update must resolve a concrete GitHub release tag, download the installer asset from that release, verify its SHA-256 from a release checksum manifest, save it locally, and execute it with `powershell.exe -File`. It must not execute mutable `main` content through `Invoke-Expression`.
- Release publishing must emit `SHA256SUMS` covering Agent, Tray, Relay and installer assets. The Windows installer must verify downloaded Windows package assets against that manifest and keep its selected release pinned through the update.
- Valheim mod install, dependency checks and uninstall must reject `.` / `..`, path separators and any path that canonicalizes outside `BepInEx/plugins`. Metadata-listed files must also be containment-checked before deletion.
- Bootstrap Admin/API token plaintext must never be written to service stdout.
- Secret state files (`appsettings.json`, `servers.json`, `tokens.json`, `public-relay.json`, and temporary/backup forms created by the Agent) must have restrictive permissions. Linux uses 0600 files, a private state directory/UMask 0077; Windows installation restricts the Agent directory ACL to SYSTEM and Administrators so subsequently-created state inherits the restriction.

## Non-goals

- Authenticated post-update health checks are BUG-02 and remain a later audit item.
- Moving SteamCMD outside the versioned Agent payload remains later cleanup.
- Reworking Linux/Relay bootstrap supply-chain behavior beyond publishing the common checksum manifest is not part of SEC-03.
- Encrypting secrets at rest is not part of SEC-05/06; this change limits local filesystem exposure.

## Approach

Use the existing GitHub Release as the trust/version boundary. The release workflow creates all assets and a checksum manifest before publication. The persistent Windows updater helper queries either the requested tag or `latest`, captures the returned tag, downloads only release assets from that response, validates the installer hash, sets `GSC_VERSION` to the captured tag, then launches the verified local installer file.

Introduce a small path-containment helper in `GameServerControl.Shared` and use it for every destructive Valheim mod path. This keeps canonicalization rules independently testable without constructing the full mod manager.

Introduce an Agent secret-file helper for Unix state-file modes and atomic writes, while deployment layers enforce process defaults: systemd `UMask=0077` and Windows installer directory ACLs. Existing token storage is migrated to the common helper rather than maintaining a separate permission implementation.

## Verification

- Add regression contract checks for release workflow/updater behavior and deployment permission defaults.
- Extend `GameServerControl.SecurityCheck` with behavioral tests for direct-child path rejection/containment and Unix secret-file modes/atomic writes.
- Run the full Windows and Linux CI matrix before merge.
