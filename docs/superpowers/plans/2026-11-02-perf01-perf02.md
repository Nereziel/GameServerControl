# PERF-01 + PERF-02 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Scope live console SignalR traffic per server and bound completed install-job memory retention.

**Architecture:** `StatusHub` owns the canonical `server:<serverId>` group name and validates subscriptions. Log producers publish only to that group. `ServerInstaller` delegates retention decisions to a pure `InstallJobRetention` helper and prunes completed jobs only at lifecycle boundaries.

**Tech Stack:** ASP.NET Core SignalR, .NET 8/C#, browser WebSocket SignalR protocol, Node.js contract checks, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-02-perf01-perf02.md`

## Global Constraints

- Work only in `Nereziel/GameServerControl`.
- Preserve existing authorization and client-side server-ID filtering.
- Active install jobs are never evicted.
- Completed-job TTL is exactly 24 hours.
- Maximum retained non-expired completed jobs is exactly 100.
- `installProgress` broadcasting is out of scope.

## Review Focus

- Unknown server subscription must fail before group membership is added.
- Read-only log consoles must join the group before starting the tail.
- Disconnect cleanup must not require a custom server-side connection registry.
- Jobs exactly around the TTL boundary must behave deterministically.
- Concurrent pruning must never remove unfinished jobs.
