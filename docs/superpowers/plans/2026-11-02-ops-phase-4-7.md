# Operations Phase 4–7 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver safer updates, capability-aware server admin, bounded monitoring history, and scalable profile metadata without changing the core Agent/Web UI architecture.

**Architecture:** Add small focused contracts/services around existing update, RCON, status and profile code. Reuse the shared Web UI and existing auth/audit middleware. Each task is independently CI-gated and backward compatible.

**Tech Stack:** .NET 8 / ASP.NET Core, vanilla browser JavaScript, PowerShell, Bash, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-02-ops-phase-4-7.md`

## Global Constraints
- Only modify `Nereziel/GameServerControl`.
- No new database or external service.
- No secrets in source, tests or logs.
- Existing `ServerDef` and `GameProfile` consumers remain source/wire compatible.
- Cloudflare continues staging the same Agent Web UI.
- Do not create a release or deploy production infrastructure.

## Review Focus
- Failed updater must restore the previous runnable payload without losing persistent configuration.
- ReadOnly users must not gain new mutating admin actions.
- Monitoring history must be strictly bounded.
- RCON actions must stay limited to handler-advertised standard commands.
- Profile validation must reject ambiguity without breaking existing curated profiles.
