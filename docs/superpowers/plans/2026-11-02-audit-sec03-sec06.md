# Audit SEC-03–SEC-06 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix the Windows updater supply-chain path, Valheim mod path traversal, and secret stdout/filesystem exposure identified as SEC-03 through SEC-06.

**Architecture:** Keep GitHub Releases as the update boundary, add one shared canonical path helper for mod filesystem operations, and centralize Agent-side Unix secret-state writes while installers enforce platform defaults. Each security property gets a regression test before production code changes.

**Tech Stack:** .NET 8 / C#, PowerShell, GitHub Actions YAML, Node.js contract tests, systemd.

**Spec:** `docs/superpowers/specs/2026-11-02-audit-sec03-sec06.md`

## Global Constraints

- Work only in `Nereziel/GameServerControl`.
- No secret values may be printed or copied into tests/logs.
- Windows updater must not execute remote script text with `Invoke-Expression`.
- Hash verification uses SHA-256 and the release asset `SHA256SUMS`.
- Path checks must use canonical full paths, not string sanitization alone.
- Linux secret files are 0600 and systemd uses `UMask=0077`.

## Review Focus

- Release asset names containing the expected installer/packages but missing from `SHA256SUMS` must fail closed.
- `.` / `..`, slash/backslash, rooted names, and prefix-confusion paths must never resolve as mod children.
- Tampered `.gsc-mods.json` file entries outside `BepInEx/plugins` must never be deleted.
- Atomic secret writes must leave the final file 0600 on Unix and avoid a permissive temporary file.
- A Windows update started by the Agent or Tray must preserve the exact resolved tag through the verified installer invocation.
