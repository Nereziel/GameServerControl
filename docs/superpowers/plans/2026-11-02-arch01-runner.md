# ARCH-01 Low-Privilege Runner Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stop Windows BareMetal game/mod processes from inheriting LocalSystem by running each managed server through its own low-privilege Windows virtual service account.

**Architecture:** Keep the existing Agent as the privileged Control Service and add a separate self-contained Runner executable. The Agent provisions one deterministic Runner service, virtual account, manifest, ACL set and named pipe per Windows BareMetal server; Runner IPC never accepts arbitrary launch metadata. Linux and Hyper-V process execution remain unchanged.

**Tech Stack:** .NET 8/C#, Windows Services/SCM, Windows virtual service accounts, named pipes, Windows ACLs, ASP.NET Core SignalR, PowerShell installer, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-11-02-arch01-runner-design.md`

## Global Constraints

- Work only in `Nereziel/GameServerControl`.
- Windows Agent remains the privileged Control Service; Windows BareMetal game/mod runtime must not execute as LocalSystem.
- Use one virtual service account per managed Windows BareMetal server.
- IPC is local named-pipe request/response only; it must not expose arbitrary executable, working-directory or argument fields in commands.
- Failure to provision Runner, ACLs or IPC must fail closed with no LocalSystem process fallback.
- Linux process execution remains under the existing unprivileged `gsc` service and is not moved to Runner.
- Hyper-V guest execution remains unchanged.
- SteamCMD install/update remains an Agent responsibility in this iteration.
- Preserve existing Satisfactory LocalSystem-profile data through the explicit compatibility bridge in the spec.
- Runner release payload is independently hashed and rolled back with Agent payload.

## Review Focus

- A malicious server ID containing SCM/pipe metacharacters must never enter a service or pipe name; deterministic names are hash-derived.
- A compromised Runner must not be able to read Agent secrets or another server's manifest/game ACL grants.
- Legacy Scheduled Tasks must be disabled before Runner becomes authoritative, preventing duplicate privileged game launches.
- Runner restart while a game survives must report process status without falsely claiming stdin attachment.
- Installer rollback must restore Runner and Agent payloads together and restart only services that were running before update.
